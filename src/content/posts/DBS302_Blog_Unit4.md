# Unit IV: Column Family Stores (Cassandra)

## Introduction

As the volume of data generated by modern applications continues to grow, traditional relational databases often struggle to provide the required scalability and performance. This challenge led to the development of NoSQL databases, which are designed to handle large-scale distributed data efficiently.

One popular NoSQL database is **Apache Cassandra**, a Column Family Store that provides high availability, fault tolerance, and horizontal scalability.

---

## What is a Column Family Store?

A Column Family Store is a type of NoSQL database that organizes data into columns rather than rows. Related columns are grouped together into a structure called a **Column Family**.

Unlike relational databases, where every row follows the same schema, Column Family Stores allow rows to have different columns, making them highly flexible.

### Key Components

* **Keyspace** – Similar to a database in relational systems.
* **Column Family (Table)** – Collection of rows.
* **Row Key** – Unique identifier for each row.
* **Columns** – Store actual data values.
* **Column Family Store** – Groups related columns together.

---

## What is Apache Cassandra?

Apache Cassandra is an open-source, distributed NoSQL database designed to manage large amounts of data across multiple servers without a single point of failure.

It was originally developed at Facebook and later became an Apache project.

### Features of Cassandra

* Distributed Architecture
* High Availability
* Fault Tolerance
* Horizontal Scalability
* Fast Read and Write Operations
* No Single Point of Failure

---

## Cassandra Architecture

Cassandra follows a **peer-to-peer architecture**, meaning all nodes in the cluster are equal.

### Components

### 1. Node

A server that stores data.

### 2. Cluster

A collection of nodes working together.

### 3. Data Center

A group of related nodes, often located in the same geographic region.

### 4. Keyspace

The outermost container for data, similar to a database.

### 5. Table (Column Family)

Stores rows and columns.

---

## Data Model in Cassandra

Example:

| Student_ID | Name     | Course                 |
| ---------- | -------- | ---------------------- |
| 101        | Tshewang | Software Engineering   |
| 102        | Sonam    | Information Technology |

In Cassandra:

* Student_ID acts as the Primary Key.
* Each row can have different columns.
* Data is distributed across multiple nodes.

---

## Cassandra Query Language (CQL)

Cassandra uses CQL, which resembles SQL but is designed for distributed systems.

### Create a Keyspace

```sql
CREATE KEYSPACE college
WITH replication = {
'class':'SimpleStrategy',
'replication_factor':3
};
```

### Create a Table

```sql
CREATE TABLE students (
student_id INT PRIMARY KEY,
name TEXT,
course TEXT
);
```

### Insert Data

```sql
INSERT INTO students
(student_id, name, course)
VALUES (101, 'Tshewang', 'Software Engineering');
```

### Retrieve Data

```sql
SELECT * FROM students;
```

---

## Replication in Cassandra

Replication means storing copies of data on multiple nodes.

### Benefits

* Improved availability
* Fault tolerance
* Faster data access
* Data recovery during failures

### Replication Factor

The replication factor determines how many copies of data are stored.

Example:

```text
Replication Factor = 3
```

The same data is stored on three different nodes.

---

## Partitioning in Cassandra

Partitioning distributes data across nodes using a **partition key**.

### Advantages

* Balanced data distribution
* Better scalability
* Improved performance

Cassandra uses a hashing mechanism to determine where data should be stored.

---

## Consistency Levels

Cassandra allows users to choose consistency levels for read and write operations.

### Common Consistency Levels

* ONE – Response from one node.
* QUORUM – Majority of replicas respond.
* ALL – All replicas must respond.

This flexibility allows applications to balance consistency and availability.

---

## Advantages of Cassandra

1. Highly scalable
2. Distributed architecture
3. Fault tolerant
4. High write performance
5. No downtime during expansion
6. Flexible schema

---

## Limitations of Cassandra

1. No complex joins like relational databases
2. Limited support for transactions
3. Data modeling can be challenging
4. Query patterns must be planned in advance

---

## Real-World Applications

Cassandra is used in:

* Social Media Platforms
* E-commerce Websites
* Messaging Applications
* IoT Systems
* Streaming Services
* Financial Applications

Organizations use Cassandra when they need to manage massive amounts of data with high availability and minimal downtime.

---

## Conclusion

Apache Cassandra is a powerful Column Family Store database designed for handling large-scale distributed data. Its peer-to-peer architecture, replication mechanisms, and horizontal scalability make it an excellent choice for modern applications requiring high availability and fault tolerance. Although it lacks some advanced relational database features, Cassandra excels in environments where scalability, performance, and reliability are critical.
